# 任务四 · 操作流程（RAG 文档问答）

> 本文件记录「端到端中文 RAG（PDF → chunk → BGE+FAISS → rerank → Qwen）」的**完整操作流程**。仓库根 `操作日志.md` 记录全局操作。
>
> 目标（一句话）：从 `data/kb.pdf`（而非 LaTeX 源）建索引，在 30 条 NNDL gold QA 上把 **Recall@10 做到 > 0.6**，并把检索质量与生成忠实性拆开量化，端到端能返回「回答 + 来源」。

**接口对齐表**（自检导入方式，务必一致）：

| 文件 | 必须导出 | 自检怎么用 |
|---|---|---|
| `src/chunker.py` | `chunk_text(text: str, chunk_size: int, overlap: int) -> List[str]`（字符计） | 平均长度 ∈ (0.5·size, 1.2·size) 且 chunk 数 > 10 |
| `src/retriever.py` | `class Retriever`：`retrieve(query: str, k: int) -> List[dict]`（含 text/score/source） | 每问调 `retrieve(q, k=10)`，命中任一 gold_anchor 记 hit |
| `src/rag.py` | `answer(query: str) -> dict(answer: str, sources: List[dict])` | answer 非空且 sources 非空（`bool(...)` 强转） |

## 2. 运行流程（按序）

### 2.1 建索引（M1 + M2）

```bash
python build_index.py                     # 默认 chunk_size=512, overlap=128 -> data/index/
python build_index.py --chunk-size 256 --overlap 64 --force   # 换参数重建（消融）
```

内部 = `data/kb.pdf` 逐页抽文本 → `chunk_text` → BGE embedding（已归一化）→ FAISS 内积索引。

- **chunk_size/overlap 以字符计**；句子尽量在 `。！？!?；;` 后断开 + overlap 保住切缝两侧。
- 向量 **L2 归一化**，FAISS 内积即余弦相似度（归一化漏了检索分数全乱）。
- 先验一下切分合理性：`python -c "from src.chunker import chunk_text; print(len(chunk_text('这是一段测试文本。'*400,256,32)))"`

### 2.2 检索召回评测（M3）

```bash
python eval/run.py
```

自检三态：`chunking_sanity`（M1）/ `nndl_gold_recall_at_10`（M3，要求 **Recall@10 > 0.6**）/ `rag_end_to_end`（M4）。

指标细节想单独看/贴报告：

```bash
python recall_report.py          # Recall@1/3/5/10 + MRR + 未命中 id
```

> 若 Recall@10 不过 0.6：先固定一档 chunk_size 把召回跑过线（读 README 实验建议），再调 chunk/加 rerank 提升上限。常见原因：chunk 太小/overlap 不足导致 anchor 落在切割缝、BGE query 前缀忘加、召回 k 太小。

### 2.3 端到端生成（M4）

```bash
# 先起本地 LLM（任选其一）：
ollama pull qwen2.5:7b-instruct && ollama serve     # OpenAI 兼容在 :11434/v1
# vLLM：python -m vllm.entrypoints.openai.api_server --model Qwen/Qwen2.5-7B-Instruct

python src/rag.py --query "什么是反向传播？请结合资料回答。"
python query_demo.py               # 内置几个问题，看答案 + 来源
```

- 服务地址/模型名可改环境变量 `RAG_LLM_BASE_URL` / `RAG_LLM_MODEL`（默认 Ollama `qwen2.5:7b-instruct`）。
- 没起服务时 `answer` 会抛带提示的 RuntimeError；只想先验证检索管道可 `RAG_OFFLINE=1 python query_demo.py`。
- `answer` 的 prompt 已写「只能用资料回答，资料不足就说不知道」+ 来源去重/长度截断 + 输出带 `(p.N)` 引用。
- 再跑一次 `python eval/run.py`：三项应全绿并写 `eval/result.json`。

### 2.4 消融 + 报告（S1~S4，任选）

| 加分 | 做法 |
|---|---|
| S1 | `build_index.py` 扫 chunk_size ∈ {128,256,512,1024} 重建索引，用 `recall_report.py` 对比 |
| S2 | 有/无 reranker 的 Recall + 端到端忠实性对比（`rag.py` 检测到 reranker 模型即自动启用） |
| S3 | Query rewriting / HyDE：在 `retrieve` 前加一层改写，量化增益 |
| S4 | RAGAS（optional 依赖）打 faithfulness / answer relevancy |

> 报告原则：检索质量（gold anchor Recall/MRR）与生成忠实性**分开说**，别用流畅答案掩盖召回失败；忠实用「答案要点是否被返回 sources 支持 / 有无资料外断言 / 是否拒答」人工抽查。

## 3. 常见坑（写代码时已规避，报错时可对照）

| 现象 | 原因 / 检查点 |
|---|---|
| `chunking_sanity` 挂 | chunk_size 按词元切 / 平均长度出 (0.5,1.2)·size。本实现按字符窗口 + 句末标点断开，overlap=32 |
| gold 召回低 / anchor 全断在缝上 | overlap 太小或 chunk 太小。默认 512/128；anchor 跨两 chunk 时 overlap 得能盖住 |
| 分数全乱 | BGE 忘了归一化；query 没加前缀 `为这个句子生成表示以用于检索相关文章：`（代码已加） |
| 自检报「索引不完整」 | 还没跑 `build_index.py`（或 data/index/ 被清）。先建索引再 eval |
| `rag_end_to_end` 失败 / 报连不上 | 本地 LLM 服务没起 / model 名不对。按 2.3 起服务，或改 `RAG_LLM_MODEL` |
| rerank 不动 / 报模型不存在 | 没下载 bge-reranker-base（`python data/download.py`）；没装则自动跳过精排 |
| 答案流畅但召回其实没中 | 以 gold anchor 召回为稳定核心指标；生成/检索分开报 |

> ⚠️ 代码只做过 `py_compile` **语法级**验证；你环境装齐依赖后首次真跑可能报运行时小错，贴回来即可快速修。
