# 任务五 · 操作流程（手写 ReAct 工具 Agent）

> 本文件记录「从零手写 ReAct 循环 + 4 类工具 + 10 题成功率评测」的**完整操作流程**。仓库根 `操作日志.md` 记录全局操作。
>
> 目标（一句话）：手写约 200 行 ReAct 循环（Thought / Action / Action Input / Observation），让本地 Qwen2.5-7B-Instruct 自主调度 calculator / python_sandbox / file_search / wiki，在自建 10 题上**答案关键词命中率 > 60%**（按关键词判定，不信任 agent 自报 `success`）。

## 0. 目录与文件结构

```
task-5-tool-agent/
├── README.md / requirements.txt / 操作流程.md
├── data/download.py          生成 10 题 tasks.json + data/agent-fixtures/ 检索夹具

│
├── src/
│   ├── __init__.py           ✅
│   ├── tools/
│   │   ├── __init__.py       ✅ 工具注册表 TOOLS（路由 + prompt 拼接）

│   │   ├── file_search.py    ✅ 文件名/内容检索（路径越界保护 + 命中预览）
│   │   └── wiki.py           ✅ 维基 MediaWiki API（中英文自动，端点可 env 覆盖）
│   └── agent.py              ✅ ReActAgent（手写循环）+ parse_step + inject_error 钩子
├── agent_demo.py             ✅ 单题/多题跑 + 打印完整 trace + 命中判定
├── tools_check.py            ✅ 4 工具独立快速自检（等价 eval M1，wiki 离线可跳过）
├── error_recovery_demo.py    ✅ 错误恢复验证（M3 / S4，第一部分无需模型）
│
├── data/tasks.json           🏃 data/download.py 产物（10 题）
├── data/agent-fixtures/      🏃 data/download.py 产物（README.md / todo_note.md）
└── eval/result.json          🏃 eval/run.py 产物
```

**接口对齐表**（自检导入方式，务必一致）：

| 文件 | 必须导出 | 自检怎么用 |
|---|---|---|
| `src/tools/{name}.py` | `TOOL_SCHEMA: dict`（OpenAI function calling 格式）+ `def run(args: dict) -> str` | 按名导入 4 个模块，用固定参数键调 run |
| `src/agent.py` | `class ReActAgent.run(task) -> dict`（含 `steps` / `final_answer` / `success`） | 每题调 `agent.run(t["task"])`，按 `final_answer` 关键词判定 |

固定参数键（模型也照此输出，键名对不上直接 KeyError→塞回 Observation 纠错）：
`calculator → {"expression": str}` · `python_sandbox → {"code": str}` · `file_search → {"pattern": str, "dir": str}` · `wiki → {"query": str}`

自检三态对照：

| 测试 | 通过标准 | 对应 |
|---|---|---|
| `tools_individual` | 4 工具单测全过；wiki 异常按「跳过」（离线/被墙）不拖累其余 | M1 |
| `multi_tool_success_rate` | 10 题 final_answer 关键词命中率 > 0.6，不信任自报 success | M4 |
| `error_recovery` | **默认跳过**（可选，S4）；我们已实现 `inject_error` 钩子，见 §2.4 | S4 |

## 1. 环境与数据

```bash
source .venv/bin/activate && cd task-5-tool-agent
pip install -r requirements.txt

# 本地模型（任选其一；默认客户端指向 Ollama OpenAI 兼容口）
ollama pull qwen2.5:7b-instruct && ollama serve
# vLLM: python -m vllm.entrypoints.openai.api_server --model Qwen/Qwen2.5-7B-Instruct
# llama.cpp GGUF 见 data/download.py 末尾打印

python data/download.py      # 生成 data/tasks.json + data/agent-fixtures/
```

**客户端环境变量**（`src/agent.py` 读取，默认即 Ollama）：

```bash
export AGENT_LLM_BASE_URL=http://localhost:11434/v1   # 或 OPENAI_BASE_URL
export AGENT_LLM_API_KEY=ollama                        # 随便填，非真 key
export AGENT_LLM_MODEL=qwen2.5:7b-instruct
export AGENT_MAX_STEPS=12    # 可选，步数上限
```

**网络注意（重要）**：wiki 工具直连 `wikipedia.org`；大陆网络常不通 → `tools_individual` 的 wiki 会显示「跳过」，这不算代码错，但 **10 题里的 4/5/9（wiki 题）会连累 M4 成功率**。解决办法：
- 有代理：`export HTTPS_PROXY=http://127.0.0.1:7890`（requests 自动走）；
- 或把 wiki 指向可达镜像：`export WIKI_API_ZH=… WIKI_API_EN=…`（见 `wiki.py`）。

## 2. 运行流程（按序）

### 2.1 工具独立自检（M1，不需要模型服务）

```bash
python tools_check.py
```

应看到 4 项全 ✓（wiki 若离线显示 [skip]，不拖累结论）。内部等价 eval 的 `tools_individual`：
- `calculator("2 + 3 * 4")` 输出含 `14`（整数会附「N 位整数」提示，辅助"结果几位数"类题）；
- `python_sandbox("print(sum(range(10)))")` 输出含 `45`；
- `file_search("README.md", ROOT)` 输出含 `README.md`（路径越界会被拒并提示）；
- `wiki("Alan Turing")` 输出长于 50 字（离线抛异常→跳过）。

### 2.2 端到端评测（M2 + M4）

```bash
# 先确认 ollama serve 起来了、模型名对
python eval/run.py
```

- `multi_tool_success_rate`：10 题逐题跑 ReAct，每题多次调模型（每题约 10–60 秒，全程数分钟）。
- 判定口径：`final_answer` 归一化（去逗号/空白/小写）后必须包含全部关键词；`["A","B"]` 表示同义变体**任一命中即可**。
- 结果写 `eval/result.json`，其中每题有 `used_tools` vs `expected_tools`、`final_answer_preview`，**直接看是哪题、漏了哪个工具、答案差在哪**。
- 单题调试看全文 trace：

```bash
python agent_demo.py --ids 5          # 看第 5 题每一步 Thought/Action/Observation
python agent_demo.py --all            # 全 10 题 + 命中汇总（不写 result.json）
python agent_demo.py --task "在 data/agent-fixtures 下找出所有 .md 文件，统计总数。"
```

### 2.3 错误恢复（M3，先离线看，后真跑）

```bash
python error_recovery_demo.py          # 第一部分（无需模型）：除零/语法错被捕获成文本，不 crash
python error_recovery_demo.py --live   # 第二部分（需模型）：向 calculator 注入 1 次故障，观察自我纠错
```

M3 的实现要点在 `src/agent.py._exec_tool`：工具任何异常都被 `except Exception` 包成
`工具 X 执行出错：…` 字符串当 Observation；`parse_step` 解析失败（缺标签/坏 JSON/未知工具）
也转成错误 Observation 要求重试——单次失败**绝不 crash 循环**。

## 3. 常见坑（写代码时已规避，报错可对照）

| 现象 | 原因 / 检查点 |
|---|---|
| 连不上模型 | `ollama serve` 没起 / base_url、model 名不对 / key 用了真 openai.com。`AGENT_LLM_BASE_URL` 默认 `http://localhost:11434/v1` |
| `tools_individual` 里 wiki 跳过 | 网络被墙，正常降级；跑 M4 前按 §1 配代理或 `WIKI_API_*` |
| 工具一直 KeyError | Action Input 键名与固定键不符（expression/code/pattern+dir/query），看 Observation 里的报错改参数 |
| Action 反复解析失败 | 7B 偶尔不守格式（多写解释/多行 JSON/单引号）。prompt 已强约束 + `extract_json_obj` 做了单引号兜底；仍失败会以 Observation 方式要求重写，步数上限兜底防死循环 |
| 某题工具没用对 | 看 `eval/result.json` 该题 `used_tools` vs `expected_tools`；多步题（5/8/9）确认 Observation 没丢（transcript 每次全量带上文） |
| 数值精度差 | 计算器对 float 给出 6 位小数写法（`sqrt(2026) → 45.011110`），最终答案照抄数字即可命中 `45.011110/45.01111` |
| 卡在某题反复错 | `agent_demo.py --ids N` 看全文 trace，区分「工具调错」还是「Action 解析失败」 |
| `python src/agent.py` 想直接跑 | 支持（文件头部加了 sys.path 引导），但建议用 `agent_demo.py` / `eval/run.py` 更直观 |

> ⚠️ 代码只做过 `py_compile` **语法级**验证；`openai/requests` 等依赖装上、模型服务起来后首次真跑可能报运行时小错，贴回来即可快速修。
