# Skill: test-runner

触发：issue/task 提到 测试、pytest、test、失败、全绿、通过。

## 步骤

1. 先 `run_tests` 拿一次基线：记录「哪个测试失败、断言期望什么」。
   - toy-repo 用默认 `python -m pytest -q` 即可。
2. 失败的断言是线索：读对应被测源码（如 `calculator.py`）与测试文件
   （**测试文件只读不改**），比对实现与期望，定位缺陷。
3. 用 `edit_file`（优先）或 `write_file` 改源码，改动**最小化**，别顺手重构无关代码。
4. 再次 `run_tests`：
   - ✅ 通过 → 输出一行 `DONE`，结束。
   - ❌ 仍失败 → 读最新失败输出末尾，回到第 2 步。连续 2 次相同失败说明
     「改错了位置」或「old_string 没对上」，先 `read_file` 拿精确文本。

## 判断"可以收尾"的唯一标准

`run_tests` 返回 ✅ pytest 通过（退出码 0）。**不**以"我觉得没问题"收尾。

## 常见坑

- 测试失败原因要看断言那几行（`assert add(2, 3) == 5` 期望 5 却得到别值 → 减法符号反了）。
- 改动后忘记重跑测试就 DONE → 大概率 M3 判定失败。
- 试图去改测试文件绕过失败 → 被工具拒绝（禁止改 test_* 与 .orig）。
