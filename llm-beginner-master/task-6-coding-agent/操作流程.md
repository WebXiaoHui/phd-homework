# 任务六 · 操作流程（Mini Coding Agent）

> 本文件记录「复刻一个本地可跑的极简 Claude Code（MCP server + Skill 加载器 + Subagent + agentic loop）在 toy-repo 上自动修通」的**完整操作流程**。仓库根 `操作日志.md` 记录全局操作。
>
> 目标（一句话）：手写 MCP server（暴露 ≥5 工具）+ Skill 加载器（2-3 个带 YAML front-matter 的 SKILL.md）+ 1-2 个 Subagent + 一条 agentic loop，在 `data/toy-repo` 上自主读懂 ISSUE、改 `calculator.add`、跑测试直到 `python -m pytest` 全绿。

```
task-6-coding-agent/
├── README.md / requirements.txt / 操作流程.md

│   ├── subagents/__init__.py  ✅ Subagents 层：explore / test_repro（独立 context）
```

**接口对齐表**（自检导入方式，务必一致）：

| 文件 | 必须导出 | 自检怎么用 |
|---|---|---|
| `src/mcp_server.py` | 顶层 `list_tools() -> List[dict]`（每个含 `name`） | import 后数工具 ≥5 |
| `src/skill_loader.py` | `class SkillLoader(skills_dir)`：`list_skills()`（每项含 name+description）、`load(name)` | `list_skills()` ≥2 且无缺元数据 |
| `src/agent.py` | `class CodingAgent.run(repo_path, issue) -> Trace`；Trace 是 dict（含 `steps`/`patch`/`tests_passed`） | 恢复 buggy → run → 外部 `pytest -q` returncode==0 |

自检四态：

| 测试 | 通过标准 | 对应 |
|---|---|---|
| `mcp_server_lists_tools` | `list_tools()` ≥5 个工具 | M1 |
| `skill_loader_metadata` | ≥2 个 skill 且都有 name+description | M2 |
| `toy_repo_patch` | 从 `.orig` 恢复 buggy 后，agent 修到外部 pytest 全绿 | M3 |
| `swebench_lite_sample` | 默认「跳过」；`--with-swebench` + clone 仓库才跑（≥1 题过） | S4 |

## 2. 运行流程（按序）

### 2.1 先离线冒烟（M1 + M2 + 工具层，无需模型）

```bash
python smoke_offline.py
```

- 验证 `list_tools()` ≥5、skill 元数据齐全、`match("跑 pytest…")` 命中 test-runner、
  read_file/edit_file 可用、write_file 拒绝 `../` 越界路径。

### 2.2 跑通 toy-repo（M3 + M4）

```bash
python run_agent.py                      # 默认 data/toy-repo + ISSUE.md
python run_agent.py --verbose            # 看每一步 Thought/Action/Observation
python run_agent.py --with-subagents --json-out trace.json   # 加分：允许派发子 agent
python eval/run.py                       # 官方自检：M1/M2/M3 +（默认跳过 S4）
```

- toy bug 是 `add(a,b)` 写成了 `return a - b`：agent 应 read ISSUE/测试 → read `calculator.py` →
  edit_file 改回 `a + b` → run_tests 全绿 → DONE。
- **eval 每轮先 `calculator.py.orig` 覆盖回 buggy** 再跑 agent，别假设上一轮已修好。
- `Trace` 每次含 `steps` / `patch`（git diff，无 git 时退 .orig 对比）/ `tests_passed`，
  自检按 `.get(...)` 取值；`tests_passed` 是**独立 pytest 终验**，不看 agent 自报。

### 2.3 MCP 独立启动（M1 的进阶路径，可选）

```bash
python src/mcp_server.py                 # 需 pip install mcp；走 stdio 握手
```

- eval 只 import `list_tools()`，**不依赖** stdio 握手；想在本机 Claude Code / MCP client 里接，
  就用上面这行把 server 作为子进程工具提供者（默认仓库由 `CODING_AGENT_REPO` 指定）。

### 2.4 加分项（S1~S4，任选）

| 加分 | 做法 |
|---|---|
| S1 | `qwen2.5-coder:7b-instruct`（FP16/量化）vs GGUF q4_k_m 成功率对比：换 `CODING_AGENT_LLM_MODEL` 重跑 |
| S2 | `--with-subagents` vs 不开，对比词元消耗与成功率（S2 关注词元/成功率） |
| S3 | `--no-skills` 关掉 Skill 注入 vs 默认，对比成功率（S3 看 Skill 增益） |
| S4 | `python data/download.py --with-swebench` + 按提示 clone 仓库到 `data/repos/`，跑 eval 的 swebench 测试 |

> 说明：SWE-bench 真实判题需官方 harness 应用 golden test_patch 再跑 FAIL_TO_PASS；本 agent 只保证
> 改对并让自己跑到的测试通过。S4 跑通 1 题即合格，难度高，跑不通不影响 M1–M4。

## 3. 常见坑（写代码时已规避，报错可对照）

| 现象 | 原因 / 检查点 |
|---|---|
| eval 报 `list_tools` ImportError | `src/mcp_server.py` 顶层必须导出 `list_tools()`（module 文件内已定义） |
| `skill_loader_metadata` 挂 | SKILL.md front-matter 缺 name/description；或扫描目录不是 `src/skills/*/SKILL.md` |
| M3 一直失败但肉眼觉得改对了 | ①确认不是上一轮残留——eval 会用 `.orig` 先复位；②看 eval 输出的 pytest 尾部是哪条断言挂；③`run_agent.py --verbose` 看 agent 是否真改了文件（edit_file 的 old_string 要对上） |
| 改了测试文件想绕过 | 被工具拒绝（test_*/conftest/*.orig 禁写）——这是有意约束，别绕过 |
| 路径越界报错 | `read/write` 传了 `../` 或仓库外绝对路径，工具会拦；要操作仓库内相对路径 |
| `python src/mcp_server.py` 起不来 | 提示装 mcp SDK / pydantic；eval 与 `run_agent.py` 都不依赖它，可先不管 |
| 长任务中间开始胡言 | 上下文撑满 → CodingAgent 内置简易压缩（约 28k 字符触发）；仍不稳可调低 `compact_at_chars` |
| 7B 忘了输出 DONE | 设计上不依赖：步数耗尽也会做独立 pytest 终验，`tests_passed` 仍然真实 |

> ⚠️ 代码只做过 `py_compile` **语法级**验证；openai/mcp/pytest 依赖 + 本地 Coder 模型 + 真实仓库
> 都在你环境首次真跑才见分晓，报错请贴回 traceback。
