# 任务四、知识图谱补全（TransE / RotatE / ConvE）

> 参考：KGE 框架 <https://github.com/Maxioo/kge_framework>
> 数据集：WN18RR、FB15k-237

---

## 一、这个任务在做什么？

**知识图谱**就是一堆「(头实体, 关系, 尾实体)」三元组，比如：

```
(姚明, 出生于, 上海)
(上海, 属于, 中国)
```

**知识图谱补全**（也叫链接预测）就是：图上缺了一条边，让模型猜出来。

```
已知： (姚明, 出生于, ?)
模型要做的事：给所有候选实体打分，把「上海」排到最前面
```

**和任务二（图上的链路预测）有什么区别？**

| | 任务二 链路预测 | 任务四 知识图谱补全 |
|---|---|---|
| 数据 | 一张图，边只有"有/无" | 三元组，边还带**关系类型** |
| 分数怎么算 | 两个节点的表示做内积/MLP | 有专门的**打分函数** `f(h, r, t)` |
| 关键点 | 学节点表示 | 同时学**实体**和**关系**的表示 |

一句话：任务二是"这两个点会不会连边"，任务是"这两个点之间是**什么关系**"。

## 三、训练和测试的脚本（作业要求必写）

| 作用 | 命令 |
|---|---|
| **训练 + 测试（单次实验）** | `python code/train.py --dataset WN18RR --model TransE` |
| **批量跑所有实验** | `python code/run_all.py --stage all` |
| **生成图表和汇总表** | `python code/plot_results.py` |
| 检查数据集 | `python code/prepare_data.py` |

**注意：本任务没有单独的 `test.py`。** 训练脚本 `train.py` 会自己完成
"训练 → 在验证集上挑最好的轮次 → 用那个轮次在测试集上评估 → 把指标写进

### 单次实验的常用参数

```bash
python code/train.py \
    --dataset WN18RR \        # WN18RR | FB15k-237
    --model   TransE \        # TransE | RotatE | ConvE
    --dim     500 \           # embedding 维度（不给就用该模型的推荐值）
    --loss    bce \           # bce(默认) | margin | 1n
    --num_neg 64 \            # 每条正样本抽几个负样本
    --lr      0.001 \         # 学习率（知识图谱要用比图神经网络更小的学习率）
    --epochs  100 \           # 训练轮数
    --eval_every 10 \         # 每几轮在验证集上评估一次
    --valid_limit 800         # 验证集最多评估多少条（加速用）
```

加 `--dry_run` 可以只打印配置不训练，用来检查参数。

## 四、数据集是怎么划分的？

数据集原本就分好了三个文件，**我们不做任何重新划分**，直接用官方划分：

| 文件 | 用途 | 作用 |
|---|---|---|
| `train.txt` | 训练集 | 用来更新模型参数 |
| `valid.txt` | 验证集 | 每若干轮评估一次，挑出最好的那一轮（**不参与训练**） |
| `test.txt` | 测试集 | 最后只用一次，报告最终结果 |

这样做是为了**防止数据泄漏**：如果拿测试集来选模型，测试结果就不可信了。

| 数据集 | 实体数 | 关系数 | 训练 | 验证 | 测试 |
|---|---|---|---|---|---|
| WN18RR | 40,943 | 11 | 86,835 | 3,034 | 3,134 |
| FB15k-237 | 14,541 | 237 | 272,115 | 17,535 | 20,466 |

**WN18RR vs FB15k-237 的区别：**
- WN18RR 来自 WordNet，实体少、关系少，但每条关系对应的实体很多（**好猜**），
  所以各模型的 MRR 普遍偏高（0.2~0.5）。
- FB15k-237 来自真实世界的 Freebase，关系有 237 种、非常细，
  很多关系在训练集里只出现过几次（**难猜**），MRR 普遍偏低（0.1~0.35）。

## 五、三个模型是怎么打分的？

设头实体向量 `h`、关系向量 `r`、尾实体向量 `t`（都是 d 维向量）。

### 1. TransE —— 「平移」：h + r ≈ t

```
分数 = -|| h + r - t ||_2          （距离越近，分数越高）
```

**直觉**：把关系看成一个**平移向量**。"上海 → 中国"就是往"中国方向"平移一步。

- 优点：参数少、训练快、可解释性强。
- 缺点：只能表达 1 对 1 关系。像"的国籍是"这种一个头实体对应很多尾实体的关系
  （1 对 N），TransE 会把所有尾实体挤到同一点上，学不好。

### 2. RotatE —— 「旋转」：h ∘ r ≈ t

```
把 h 和 r 都看成复数向量，元素两两相乘（复数乘法）
分数 = γ - || h ∘ r - t ||        （γ 是 margin，默认 6.0）
```

**直觉**：关系是**复平面上的旋转**。`r` 的每个分量是单位复数 `e^{iθ}`，
作用到 `h` 上就是把它转 θ 角度。

- 关键约束：`|r| = 1`（模长恒为 1），所以旋转不会改变向量长度。
- 好处：**方向可以转，长度不变**，于是能同时表达 1对N、N对1、对称、反对称关系 ——
  正好补上 TransE 的短板。
- 实现细节：实体用 `dim*2` 维实数存（实部+虚部各 `dim` 维），关系只存 `dim` 个相位角。

### 3. ConvE —— 「卷积」：用 CNN 打分

```
1. 把 h 和 r 的向量拼起来，reshape 成 10 × (2d/10) 的二维矩阵
2. 过一层 2D 卷积 + BatchNorm + ReLU + Dropout
3. 拉平后过一层全连接，得到向量 x
4. 分数 = x · t + bias_t
```

**直觉**：TransE 的加法、RotatE 的乘法都是**逐元素**操作，交互太简单。
ConvE 用**卷积**让 h 和 r 的不同维度之间产生更复杂的交互。

- 优点：表达能力强，FB15k-237 上通常比 TransE 好。
- 缺点：慢。评估时要给每个候选实体都过一遍卷积，比前两个模型慢一个数量级。

## 六、评估指标怎么算的？

对每个测试三元组 `(h, r, t)`：

```
1. 固定 h 和 r，用模型给**所有实体**当尾实体的分数排名  → 看 t 排第几
2. 固定 r 和 t，用模型给**所有实体**当头实体的分数排名  → 看 h 排第几
3. 两个方向的排名取平均，作为这条三元组的排名
```

| 指标 | 含义 |
|---|---|
| **MRR** | 排名的倒数的平均值。第 1 名得 1 分、第 2 名得 0.5 分、第 10 名得 0.1 分。越大越好 |
| **Hits@1** | 正确答案排第 1 名的比例 |
| **Hits@3 / Hits@10** | 排进前 3 / 前 10 名的比例 |
| **平均排名** | 名次的平均值，越小越好 |

### 两个容易被忽略但很重要的细节

1. **过滤式评估（Filtered Setting）**
   同一个 `(h, r)` 可能对应多个正确的尾实体。比如 `(姚明, 出生于, 上海)` 和
   `(姚明, 出生于, 松江)` 都是对的，但我们只测了其中一个。
   如果排名时把"其他也对的答案"算进去，正确名次会被白白拉低。
   所以评估前先查一遍训练/验证/测试集里所有 `(h, r, *other)`，
   给它们的分数置成 `-inf`，不让它们参与比较。
   **代码位置**：`train.py` 的 `build_filter_index()` 和 `evaluate()`。

2. **方向平均**
   业界报告结果时都是"猜尾 + 猜头"两个方向取平均，只报一个方向的数据
   和别人没法比。

## 七、关于损失函数：为什么默认是 `bce` 而不是 1-N 打分？

这是本任务踩过的最大一个坑，记录在这里。

### 三种损失函数

| `--loss` | 做法 | 特点 |
|---|---|---|
| `bce`（**默认**） | 负采样 + 二分类交叉熵：正样本标签 1、负样本标签 0 | 三个模型通用，对比公平 |
| `margin` | 负采样 + 排序损失：要求"正样本分数 - 负样本分数 ≥ margin" | TransE/RotatE 原论文用的，但损失为 0 时还会漂移 |
| `1n` | 1-N 打分：**不采样**，一次给**所有实体**打分，同时把全部负样本压低 | ConvE 论文里的做法，快，但**只适合 ConvE** |

### 坑：1-N 打分用在 TransE/RotatE 上会「虚假收敛」

现象：用 `--loss 1n` 训练 TransE，损失一路降到 0.0168，看起来完美，
但测试 **MRR ≈ 0.0008**（基本等于瞎猜）。

原因：TransE 的分数是 `-||h + r - t||`。1-N 打分要求"给所有负样本都打低分"，
而**只要把 `h + r` 推到无穷远**（让向量范数爆炸），就能让所有分数一起变低，
损失瞬间就降下去了 —— 但模型根本没学到任何语义。

这是**距离型模型特有的退化逃逸路径**。RotatE 同理（它也是距离型）。
ConvE 是内积型，分数有界，不受影响。

**结论：`--loss` 默认用 `bce`（负采样二分类），三个模型一视同仁。**

### 坑：负采样时不要开标签平滑

现象：负采样 + `--label_smoothing 0.1` 训练 TransE，损失**死死卡在 0.3526 不动**。

原因：标签平滑把正负样本标签从 `1 / 0` 改成 `0.9 / 0.1`。
每个正样本只配 64 个负样本时，BCE 的理论下界变成
`-0.9·ln0.9 - 0.1·ln0.1 ≈ 0.325`。模型学到"正样本 σ≈0.9、负样本 σ≈0.1"
这点区分度之后，损失就再也降不下去了。

标签平滑在 **1-N 打分**里是有用的（因为一次要面对几万个负样本，
不平滑会导致正样本被淹没），但在负采样里只会**人为加一个损失下界**。

所以代码里拆成两个参数：
- `--label_smoothing`（默认 0.1）—— **只在 `--loss 1n` 时生效**
- `--neg_label_smoothing`（默认 **0.0**）—— 只在 `--loss bce/margin` 时生效

### ⚠️ 坑（最隐蔽的一个）：权重衰减必须设成 0

**这个坑比上面两个都隐蔽，因为它不会报错，只会让结果悄悄变得很差。**

`utils.py` 给所有任务统一设的默认 `weight_decay=5e-4`，
对图神经网络是合理的，但用在知识图谱模型上**几乎是致命的**。

实测（WN18RR + TransE + dim=100，其他条件完全一样，都跑 12 轮）：

| 权重衰减 | 训练损失（1 轮 → 12 轮） | 验证 MRR | 判断 |
|---|---|---|---|
| `5e-4`（通用默认值） | 0.0858 → 0.0857（**几乎不动**） | **0.0007** | 基本等于没学 |
| `0`（正确设置） | 0.0836 → 0.0594（稳定下降） | **0.0936** | 正常学习 |

**相差 130 倍**，而且从日志上看不出任何异常 —— 损失没变成 NaN，
没报错，程序正常跑完，只是结果全是垃圾。
这正是这类 bug 最危险的地方：**它成功地产出了一份看起来正常的错误结果**。

#### 为什么 Adam + 权重衰减 对 KGE 这么致命？

Adam 的更新方式是"把梯度除以它自身的二阶矩"，也就是**把更新幅度归一化**，
不管梯度多大，每步走的路程都大约是 `lr`。

而 L2 正则的做法是把 `wd × 参数` 加进梯度里。在普通 SGD 下，
这是个很小的收缩力；但在 Adam 下，这一项**也会被归一化到 `lr` 量级**：

```
真实梯度贡献的更新量   ≈ lr
权重衰减贡献的更新量   ≈ lr        ← 两者一样大！
```

于是权重衰减在 Adam 下不再是"轻微的收缩"，而变成了一个
**和真实学习信号同量级的、恒定把参数往 0 拉的力**。
而 KGE 模型的参数几乎全是 embedding（每个实体一个自由向量、
参数之间没有权重共享），被这么一直往 0 拉，就彻底学不动了。

#### 结论

知识图谱模型一律 `weight_decay = 0`。这也是 KGE 论文和主流实现
（TransE / RotatE / ConvE 官方代码、OpenKE、kge_framework）的通行做法。

代码里已经写死：

```python
# run_all.py
DEFAULT_WD = 0.0            # 不是 5e-4！
...
"--weight_decay", str(DEFAULT_WD),     # 显式传给 train.py
```

`KEY_FIELDS` 里也加了 `weight_decay` 字段，这样万一有人用别的值跑过，
那批结果不会被误认为"已经跑过了"而跳过。

> 💡 **同样的道理也适用于 `--lr`**：通用默认值 `0.01` 是给 GNN 的，
> KGE 必须用 `0.001`。`run_all.py` 里也是显式传的（`DEFAULT_LR = 0.001`）。
> 这两个参数都已经在 `run_all.py` 里写死，你直接跑就不会踩坑。

## 八、对比实验的设计

`run_all.py` 里有三组实验，对应报告要求：

### `--stage main` 主实验（6 次）

```
3 个模型 × 2 个数据集 = 6
```

回答报告要求 3.1 的"**不同的神经网络对性能的影响**"。

### `--stage dim` embedding 维度（9 次）

```
3 个模型 × dim ∈ {100, 200, 500}，在 WN18RR 上做 = 9
```

回答报告要求 3.1 的"**不同参数对性能的影响**"。

> **⚠️ 关于"网络层数"的说明（重要）**
>
> 报告要求 3.1 写的是"学习率、**网络层数**"。但任务四的三个模型**都没有"层数"这个
> 超参数**：
> - TransE 就是 `h + r ≈ t` 一个公式，没有层；
> - RotatE 就是复数乘法 `h ∘ r ≈ t`，也没有层；
> - ConvE 是"一层卷积 + 一层全连接"，加层数不是它的常规用法
>   （卷积层数一多，`10 × (2d/10)` 这种小特征图立刻被卷没了）。
>
> 所以在任务四里，**"网络容量"这个维度用 embedding 维度 `dim` 来消融**，
> 对应 `--stage dim` 和 `fig2_dim_effect.png`。这是知识图谱领域的标准做法：
> KGE 论文里的参数敏感性实验做的都是 dim。
>
> 如果一定要看"层数"，可以看 ConvE：它内部是 1 层卷积 + 1 层全连接，
> 改层数等价于改成另一种模型，已经超出本任务范围。

### `--stage lr` 学习率（12 次）

```
3 个模型 × lr ∈ {1e-4, 5e-4, 1e-3, 5e-3}，在 WN18RR 上做 = 12
```

回答报告要求 3.1 的"**学习率的影响**"。

### 全部一起跑

```bash
python code/run_all.py --stage all
```

**断点续跑**：所有结果都追加写进 `results/results.jsonl`。中途中断后
重新运行会自动**跳过已经跑完的实验**（按"数据集+模型+dim+学习率+损失函数+种子"
判断）。想全部重跑加 `--no_skip_done`。

**`--stage lr` 和 `--stage main` 有重叠**：`lr=1e-3` 那一组就是主实验的配置，
所以先跑了主实验再跑 lr 消融，重复的那 3 个会被自动跳过。

## 九、耗时提示（很重要）

知识图谱数据集比图分类大得多（FB15k-237 有 27 万条训练三元组），
评估又要"给所有实体排名"，所以这组实验**明显比其他任务慢**。

| 操作 | 大致耗时 |
|---|---|
| WN18RR / TransE 每轮训练 | 2~4 秒 |
| WN18RR / ConvE 每轮训练 | 5~10 秒 |
| WN18RR 测试集评估（3134 条 × 2 方向） | 约 3~4 分钟 |
| FB15k-237 / ConvE 测试集评估 | 约 8 分钟 |

**建议**：
- 跑之前先用 `python code/run_all.py --stage main --dry_run` 看看规模；
- 用 `--valid_limit 800` 限制验证集评估条数（默认已开）；
- 显卡被别的任务占满时，本任务的每轮耗时会暴涨几十倍
  （显存不够会退化成走 PCIe 的共享显存），**建议单独跑**。
