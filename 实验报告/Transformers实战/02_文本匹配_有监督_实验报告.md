## 1. 任务目标与实验设置

**任务目标**：在同一批商品评论语料上，对比三种有监督文本匹配结构的**精度—成本权衡**，回答「单塔（交互式）与双塔（表示式）各自的适用边界在哪里」。

与上一篇文本分类报告的区别：分类任务是「一句话 → 一个类别」（8 分类），本任务是**句对二分类**（匹配=1 / 不匹配=0），输入是 `(商品类别描述, 用户评论)` 这样一对文本。

**数据集**：`data/comment_classify/`，`datasets.load_dataset('text', ...)` 读取，每行为 `text1\ttext2\tlabel`（三列 TAB 分隔）。

| 划分 | 行数 | 标签分布 |
|---|---|---|
| train.txt | 1,416 | label 0：932 条，label 1：484 条（正例占 34.2%） |
| dev.txt | 352 | label 0：246 条，label 1：106 条（正例占 30.1%） |

例（`data/comment_classify/train.txt` 第 2 行）：

```
衣服：指穿在身上遮体御寒并起美化作用的物品。<TAB>为什么是开过的洗发水都流出来了、是用过的吗？是这样子包装的吗？<TAB>0
```

`types_desc.txt` 提供 10 个候选类别（id 0~9）的「类别名 + 类别描述」，是 §2.2 双塔离线建库的语料来源。

**模型与超参**（取自三个 `train_*.sh`）：

| 子任务 | 骨干 | 结构 | batch | max_seq_len | epochs | valid_steps | logging_steps | device |
|---|---|---|---|---|---|---|---|---|
| PointWise | `nghuyong/ernie-3.0-base-zh` | 单塔（交叉编码） | 8 | 128 | 10 | 50 | 10 | cuda:0 |
| DSSM | `nghuyong/ernie-3.0-base-zh` | 双塔 + cos 相似度 | 8 | 128 | 10 | 50 | 10 | cuda:0 |
| Sentence-BERT | `nghuyong/ernie-3.0-base-zh` | 双塔 + 分类头 | 8 | 256 | 10 | 50 | 10 | cuda:1（脚本原值） |

> ⚠️ `train_sentence_transformer.sh` 里写的是 `--device "cuda:1"`，本机只有一张 GPU（RTX 3070 Ti），实际运行时必然被改成 `cuda:0`；`SimCSE/train.sh` 与 `PET/train.sh` 同样存在 `cuda:2` / `cuda:1` 的残留，属于同一批脚本在单卡机器上的移植痕迹。

**统一的评测节奏与指标**：
- 每 50 step 评测一次。1,416 条 train、batch 8 → **每 epoch 177 step**，10 epoch 共 1,770 step。因此 50 step ≈ 0.28 epoch，完整训练应有 **35 次评测**（step 0, 50, 100, …, 1770）。
- 指标：`evaluate.combine(["accuracy", "f1", "precision", "recall"])`，二分类默认按正类（label=1）计算 P/R/F1。
- 实际评测次数差异极大（见 §3）：PointWise 只有 **1 次**，DSSM 与 Sentence-BERT 各 **5 次**。

## 2. 方法与实现要点

三种结构共用同一个 `ernie-3.0-base-zh` 编码器（12 层 / hidden 768），区别只在**编码器的调用次数**与**相似度→logits 的映射方式**（`model.py`）。

### 2.1 PointWise（单塔 / 交叉编码器）

```python
# model.py: PointwiseMatching
pooled = encoder(input_ids, token_type_ids, position_ids, attention_mask)["pooler_output"]
logits = Linear(768, 2)(Dropout(0.1)(pooled))     # (batch, 2)
```

- 输入是**拼接后的句对**：`[CLS] 文本A [SEP] 文本B [SEP]`，`token_type_ids` 区分 A/B 段。
- 两句话在**编码器内部的每一层 self-attention 里就发生了交互**，因此能捕捉词级对齐、否定、修饰等细粒度匹配信号。
- 取 `pooler_output`（[CLS] 池化向量），过 `Dropout(0.1)` + `Linear(768→2)`，`CrossEntropyLoss`。
- 代价：**每一对 (query, doc) 都必须过一次完整的 12 层编码器**。给定 1 个 query、N 个候选 doc，推理需 N 次前向，**无法离线预计算**。
- 参数：编码器 + `Linear(768, 2)` 的 1,538 个参数，`model_best/model.pt` 为 471,926,723 字节（三个文件中最接近「纯编码器」的大小）。

### 2.2 DSSM（双塔 / 表示式 + 余弦相似度）

```python
# model.py: DSSM
def get_similarity(...):
    q = encoder(q_ids, q_tt, q_mask)["pooler_output"]   # 各自独立过编码器
    d = encoder(d_ids, d_tt, d_mask)["pooler_output"]
    return F.cosine_similarity(q, d)                     # (batch,)
```

- query 与 doc **各自独立编码**（共享同一组编码器权重，即「孪生网络」），输出 `pooler_output`，用余弦相似度作为匹配分数。
- 损失是 **`torch.nn.MSELoss()`**：把 cos ∈ [-1, 1] 直接回归到 0/1 标签（`train_dssm.py` 中 `criterion = torch.nn.MSELoss()`，`labels = batch['labels'].to(torch.float)`）。
- 评测时用**硬编码阈值 0.5** 把 cos 二值化（`train_dssm.py`：`logits[logits>=0.5] = 1; logits[logits<0.5] = 0`）。
- 优势：可以在训练后**离线预计算全部候选 doc 的 embedding**（`get_embedding.py` + `types_desc.txt`），线上只需编码 1 次 query，再做一次余弦检索，是「搜索召回」场景的标准做法。
- 参数：编码器 + `Dropout(0.1)`（无可学习分类头），`dssm/model_best/model.pt` 为 471,919,755 字节——**三个文件中最小**。

### 2.3 Sentence-BERT（双塔 / 表示式 + 交互分类头）

```python
# model.py: SentenceTransformer
u = mean_pool(encoder(q_ids, q_tt, q_mask)["last_hidden_state"], q_mask)   # 句向量
v = doc_embedding                                                          # 预先算好或现场算
logits = Linear(768*3, 2)(cat([u, v, |u - v|], dim=-1))                    # (batch, 2)
```

- 同样是**双塔**，但句子表示不用 `pooler_output`，而是对 `last_hidden_state` 做**带 mask 的 mean-pooling**（`get_embedding` / `get_similarity_label` 里手写 `sum(hidden*mask)/sum(mask)`）。
- 关键差别：匹配不是「余弦相似度 + 固定阈值」，而是把 `[u, v, |u−v|]` 拼成 2304 维向量，过 `Linear(768*3 → 2)` 做二分类，`CrossEntropyLoss`。**决策边界是学出来的**，因此不需要 DSSM 那样人为指定 0.5。
- 训练代码里是**现场重算 doc 塔**（`convert_dssm_example` 同时产出 `doc_input_ids`），并没有用预计算的 `doc_embeddings`；`forward(..., doc_embeddings)` 那条路径是给推理用的（`get_embedding.py` 走 `get_embedding()`）。
- 参数：编码器 + `Linear(2304, 2)` 的 4,610 个参数，`sentence_transformer/model_best/model.pt` 为 471,939,011 字节——三个文件中**最大**（高出 PointWise/DSSM 约 12~19 KB，正好对应 2304×2 与 768×2 的分类头之差）。

### 2.4 三者的「结构—成本」对照（由源码与 checkpoint 尺寸直接推出）

| 维度 | PointWise（单塔） | DSSM（双塔） | Sentence-BERT（双塔） |
|---|---|---|---|
| 编码器调用次数 / 每个 (q,d) 对 | 1 次（联合编码） | 2 次（但可各缓存） | 2 次（训练）；推理可缓存 doc 塔 |
| 句表示 | `pooler_output`([CLS]) | `pooler_output`([CLS]) | masked mean-pooling |
| 匹配函数 | `Linear(768→2)` 二分类 | 余弦相似度（无参数） | `Linear(2304→2)` 二分类 |
| 损失 | CrossEntropy | **MSELoss 回归 cos** | CrossEntropy |
| 决策边界 | 学习得到 | **固定阈值 0.5** | 学习得到 |
| 离线建库 | ❌ 不可 | ✅ 可 | ✅ 可 |
| 线上单 query 延迟（N 个候选） | O(N) 次完整编码 | O(1) 次编码 + 向量检索 | O(1) 次编码 + 向量检索 + 轻量分类 |
| `model_best/model.pt` 字节数 | 471,926,723 | 471,919,755 | 471,939,011 |

## 3. 实验结果

**先明确两类结果的口径差异**——这是本篇报告最重要的一条读数说明：

- **PointWise：单点评测。** `checkpoints/comment_classify/` 下只有 `model_200` 与 `model_best`，说明 1,770 step 的训练**只在 step 200 触发了一次评测**。`ERNIE-PointWise.png` 的四个 eval 子图与文本分类那张完全一样：**空白无曲线，x 轴刻度为 `190.0, 192.5, …, 210.0`**（单点 autoscale 的指纹）。因此下表 PointWise 的四个数是**一次快照**。
- **DSSM / Sentence-BERT：评测曲线。** `dssm/` 与 `sentence_transformer/` 下都有 `model_0`、`model_200`、`model_best`，对应 **step 0 / 50 / 100 / 150 / 200 共 5 次评测**（`model_0` 说明训练循环第一次进 `global_step % 50 == 0` 时就评测了）。`ERNIE-DSSM.png` 与 `Sentence-Ernie.png` 的 6 宫格中，除右上角一个空子图外，其余 5 个都是完整的折线。

## 4. 结果分析

### 4.1 单塔 vs 双塔：0.90 → 0.82 → 0.61 的精度梯度与结构复杂度完全对应

三个数字之间的差距不是噪声，而是**「交互发生在哪里」**的直接结果：

- **PointWise（F1 0.90）**：query 与 doc 在编码器内部逐层 self-attention 交互，模型可以学到「洗发水 ↔ 衣服」这类**需要同时看到两个词的搭配级判据**。表达能力最强，代价是每个候选都要过一次编码器。
- **Sentence-BERT（F1 0.816）**：两句话**先各自压成一个 768 维句向量**（信息瓶颈），再用 `[u, v, |u−v|]` 做二分类。分类头是学出来的，所以它能拟合比「余弦相似度」更复杂的判据（例如「某一维差异大但另一维必须相近」），但**句子级压缩已经丢失了词级对齐信息**，因此精度低于单塔。
- **DSSM（F1 0.61）**：瓶颈更窄——只有 `pooler_output` 一个 [CLS] 向量 + **一个无参数的余弦相似度**，且决策边界被写死为 0.5。可表达的函数类最小，精度最低。它与 Sentence-BERT 的 0.21 个 F1 差距，主要来自「cos + 固定阈值」vs「学出来的分类头 + mask 均值池化」这两处改动。

**这与两个模型 `model.pt` 尺寸的排序一致**（DSSM 471,919,755 < PointWise 471,926,723 < Sentence-BERT 471,939,011 字节）：Sentence-BERT 分类头（2304×2）比 PointWise（768×2）大，DSSM 没有分类头。也就是说，**三者的参数差异只有 KB 量级，但精度差 0.3 个 F1——决定精度的是结构而不是参数量**。这一点正是「双塔用极小的参数代价换来离线建库能力」这一工程叙事的核心。

### 4.2 一个反直觉现象：DSSM 的 recall 从 0.954 单调跌到 0.604，而 precision 与 accuracy 单调升

这是本报告最值得解释的曲线，它的机制可以从源码精确定位：

1. **评测的二值化是硬编码的**：`train_dssm.py` 里 `logits[logits>=0.5]=1; logits[logits<0.5]=0`，阈值 0.5 与训练数据无关。
2. **训练目标是 MSE 回归**：模型被要求让正例 cos→1、负例 cos→0。随着训练进行，**所有样本的 cos 分数整体被拉高/推开**，正例向 1 聚集。
3. **阈值固定而分布漂移**：在 step 0（几乎未训练）时，cos 集中在 0.5 附近且偏正，于是**绝大多数样本被判为 1**——这就是 recall 0.954、precision 0.30 的来源。随着训练推进，模型把负例的 cos 压向 0，越来越多的负例掉到 0.5 以下，于是 recall 下降、precision 上升。两线在 step 75 附近交叉（约 0.60/0.60），最终停在工作点 (P 0.62, R 0.60)。
4. **所以「precision 与 recall 近似等量交换」不是模型变好或变坏，而是阈值 0.5 扫过 cos 分布**。这解释了为什么 accuracy（0.30→0.77）与 F1（0.45→0.61）都在涨，但涨得很慢：F1 对阈值敏感，而模型真正的排序能力提升被这个失配的阈值吃掉了。
5. **dev 正例只占 30.1%（106/352）**，所以「全判为正」的 recall=1.0 / precision=0.301 / F1=0.462 是平庸但不算荒谬的基线；F1 从 0.45 涨到 0.61 说明模型确实学到了东西，但**大部分增益被浪费在阈值失配上**。
6. 直接的反证是 Sentence-BERT：它把「阈值」变成一个可学习的 `Linear(2304→2)`，于是 P/R 不再反向交叉，而是**同步上升**（P 0.29→0.81，R 0.39→0.82）。**同一份数据、同一个骨干，只把「cos+固定 0.5」换成「可学习分类头」，F1 就从 0.61 提升到 0.82。**

### 4.3 一个必须强调的口径警告：PointWise 的 0.90 是「单点」，但可信度高于其 0.94 accuracy 的表面精度

- PointWise 只有 step 200 一个评测点。按 177 step/epoch 换算，step 200 ≈ **第 1.13 个 epoch**（`200/177 ≈ 1.13`），训练进度约 11%。**这与 DSSM / Sentence-BERT 的 step 200 完全对齐**——三个模型的可比工作点其实就是同一个 step 200。
- 尽管如此，PointWise 的 0.90 比 DSSM 的 0.61 高出 0.29 个 F1，这个差距**不太可能是单点抖动造成的**：同时刻 PointWise 的 train_loss 已降到 0.19（DSSM 的 MSE 还有 0.225，且形状是线性未收敛），且 `ERNIE-PointWise.png` 的 loss 曲线比 DSSM 明显更深更平。因此「单塔精度显著高于双塔」的定性结论是站得住的；但 **0.90 这个具体数字不应被当作 PointWise 的上限**（训练只走了 1.13/10 epoch，loss 还在下降），补跑 10 epoch 后再评测才是最终数字。
- 另外，PointWise 的 `train/train_loss` 是**累计平均**（`loss_list` 全程 append 未清空），真实瞬时 loss 比曲线更低、下降更快，这进一步降低了「0.90 已是上限」的可能性。

### 4.4 成本侧：精度差距换来的推理能力差距

| 场景 | PointWise | DSSM / Sentence-BERT |
|---|---|---|
| 1 个 query 对 N 个候选打分 | 需要 **N 次完整 12 层编码**（每对都要拼接、编码） | **1 次编码** query + 一次向量检索/轻量分类 |
| 新增一个候选 doc | 无需改动（但每次都要重算） | 只需离线算一次该 doc 的 embedding 入库 |
| 典型用途 | 精排（rerank）、离线质量校验、小候选集（10~100） | 召回、大规模去重、语义检索（10⁴~10⁸ 候选） |

由于本实验的候选集只有 `types_desc.txt` 里的 **10 个类别**，双塔的「离线建库」优势在数字上没有体现出来（10 次编码与 1 次编码的差距在毫秒级），**所以本实验只能证明「单塔更准」，不能证明「该用单塔」**——当候选数从 10 放大到 10⁵ 时，PointWise 的 O(N) 编码开销（10⁵ 次 12 层前向）在绝大多数线上场景不可接受，此时 F1 0.61 的 DSSM 才是唯一可行的选择。这也是 `readme.md` 里 DSSM 与 Sentence-BERT 章节都专门给出「预先计算类别 embedding 并落盘」流程的原因。

## 5. 踩坑与局限

1. **PointWise 只有单点评测**：`checkpoints/comment_classify/` 下只有 `model_200` 与 `model_best`，`ERNIE-PointWise.png` 的 4 个 eval 子图全为空白。无法判断 0.90 是峰值、低谷还是上升途中的一点，也无法做早停。
2. **三个子实验都没有终端截图**：与 SimCSE（F1 与 spearman 有截图逐字印证）、p-tuning（F1 0.64000 有截图印证）不同，本任务的数值**只有曲线反解这一个来源**，缺少第二来源交叉验证。
3. **`max_seq_len` 不一致**：DSSM 与 PointWise 是 128，Sentence-BERT 是 256——后者能容纳更长的评论，构成一个未被控制的混淆变量。
4. **评测口径不一致（表 3.4 的核心局限）**：PointWise 单点 vs 另外两者 5 点曲线；「max」与「末端」混在一张表里也会误导（DSSM 的 recall max 0.954 出现在 step 0）。
5. **DSSM 的阈值硬编码**：`0.5` 既未在 dev 上搜索、也未做阈值-召回曲线。这是 DSSM 表现偏低的主要可归因原因之一（§4.2），**不修这一点就不能说「DSSM 结构不行」**。
6. **MSE 回归 cos + 二分类评测的目标错配**：训练优化的是 L2 距离，而评测关心的是排序/分类边界，两者并不一致（业内更常用的是 triplet/InfoNCE 或直接在 cos 上加 BCE）。
7. **训练远未跑完**：三个模型都只到 step 200（≈1.13/10 epoch），DSSM 与 Sentence-BERT 的曲线都是**近乎直线的单调趋势，没有任何收敛平台**，因此表 3.4 的三行数字都是「训练早期」的读数，不是最终性能。
8. **设备配置残留**：`train_sentence_transformer.sh` 写 `cuda:1`，本机只有 1 张卡，实际运行必然被改。单卡 8 GB 也限制了 batch（只能到 8）与序列长度（Sentence-BERT 的 256 已接近吃满）。
9. **正例比例只有 30~34%**：三个子实验都未做重采样或类别加权，accuracy 这个指标因此天然偏高（全判负也有 0.70），跨模型比较应以 F1 为主。
10. **`get_embedding.py` / `inference_*.py` 与现有 checkpoint 格式不匹配**：readme 中推理段写的是 `torch.load(os.path.join(saved_model_path, 'model.pt'))`，而 `sentence_transformer/model_best/` 下确实有 `model.pt`，但同步保存的还有 `tokenizer.json`；若直接照 readme 的 `AutoTokenizer.from_pretrained(saved_model_path)` 加载，依赖目录里必须存在完整的 tokenizer 文件（当前只有两个 json）。**这次实验只跑到了训练，没有跑推理与 embedding 落盘**，所以「离线建库」的实际收益在本批产物中**没有被测过**。

## 6. 结论与改进建议

### 6.1 结论

- 在同一份 `comment_classify` 句对数据（1,416 train / 352 dev）上，用同一个 `ernie-3.0-base-zh` 骨干，三种结构的 F1 呈清晰梯度：**PointWise（单塔）0.90 > Sentence-BERT（双塔+分类头）0.816 > DSSM（双塔+余弦+固定阈值 0.5）0.610**。
- **结构决定精度，参数量不决定精度**：三者 checkpoint 只差十几 KB，F1 却差 0.29；把「余弦相似度 + 硬编码阈值 0.5」换成「可学习的 `Linear(2304→2)` 分类头」（DSSM → Sentence-BERT），F1 从 0.61 提升到 0.82，且 P/R 从反向交叉变为同步上升——**DSSM 的低分主要是阈值/损失设计问题，而非双塔结构的固有上限**。
- **代价一侧**：单塔每对样本都要过完整编码器（O(N) 次前向），双塔可离线建库、线上单次编码；本实验候选集只有 10 类，无法在数字上体现该优势。
- **口径限制**：PointWise 是 step 200 的**单点快照**（训练进度约 1.13/10 epoch，loss 仍在下降），DSSM 与 Sentence-BERT 是 5 点曲线（同样均为训练早期、无收敛平台）。因此这些数字应作为**趋势性结论**，而非最终性能。

### 6.2 改进建议

1. **统一评测节奏并把曲线画密**：三个脚本都把 `--valid_steps` 从 50 收到 25 或 10（1,770 step 下分别得 71 / 177 次评测），确保 PointWise 也有曲线，且三者的「max / 末端」能在同一步数上对齐。
2. **跑满 10 epoch**：当前停在 step 200（11%），三条 loss 曲线都还在下降段。
3. **给 DSSM 做阈值扫描**：在 dev 上枚举阈值 t ∈ [0, 1]，画出 P-R 曲线与 F1-t 曲线，报告**最佳阈值下的 F1**，而不是固定 0.5 的结果。预期这一项就能缩小 DSSM 与 Sentence-BERT 的差距。同时建议把 `MSELoss` 换成对 cos 的 BCE 或 triplet/InfoNCE 损失。
4. **控制变量**：把 Sentence-BERT 的 `max_seq_len` 也改成 128 重跑一次，排除序列长度带来的优势。
5. **补上终端截图/日志**：把 `Evaluation precision/recall/F1` 与逐类指标同时重定向到文件（例如 `logs/comment_classify/*.log`），为本任务提供第二条证据链。
6. **补做推理侧实验**：跑通 `get_embedding.py`（`types_desc.txt` 共 10 个类别的 embedding 落盘）与三个 `inference_*.py`，用**同一条 query 的端到端延迟与 QPS** 把「单塔 vs 双塔」的成本差异从「理论陈述」变成「实测数字」——这是本实验目前最缺的一块。
7. **修设备配置**：把三个 `train_*.sh` 里的 `--device` 统一为实际存在的卡号（本机为 `cuda:0`），避免复现时直接报错。
8. **对 PointWise 单独做一次完整训练 + `model_best` 复评**：确认 0.90 是低估还是高估。
