## 1. 任务目标

对应作业 [任务二、图上的链路预测](../../graph_beginner-main/README.md) 的四条要求：

1. 基于现有图神经网络框架实现图上的链路预测；
2. 使用 Cora、Citeseer、Flickr 三个数据集；
3. 测试 GCN、GAT、GraphSAGE、GIN 四种模型；
4. 利用框架自带的 Sampler 采样子图进行训练，并与全图训练进行**性能**和**运行时间**的对比。

同时对应作业「报告要求」3.1 中「不同神经网络对性能的影响」与 3.2 中属于本任务的部分
（全图 vs 分批次）。

**链路预测的定义**：把图中一部分边藏起来，让模型判断任意两个节点之间「本来有没有边」，
本质是二分类：正样本为真实边，负样本为随机抽取的不存在边。
与任务四（知识图谱补全）的区别在于：本任务的边没有关系类型，只学节点的表示；
任务四还要同时学实体与关系的表示，并使用专门的打分函数 `f(h, r, t)`。

## 2. 数据集与实验设置

### 2.1 数据集

| 数据集 | 节点数 | 边数 | 特征维度 | 特点 |
|---|---|---|---|---|
| Cora | 2,708 | 10,556 | 1,433 | 论文引用网络 |
| Citeseer | 3,327 | 9,104 | 3,703 | 特征更稀疏、边更少 |
| Flickr | 89,250 | 899,756 | 500 | 规模约为 Cora 的 33 倍 |

### 2.2 边的划分（本任务的核心设置：无泄漏）

链路预测的样本是「边」，划分时必须防止信息泄漏。代码的流程是：

1. 图转为无向图并去掉自环；
2. **只保留 `u < v` 的边**，得到唯一的无向边集合（每条边只算一次）；
3. 随机打乱后按 **85% / 5% / 10%** 划分为训练边 / 验证边 / 测试边
   （`--val_ratio 0.05`、`--test_ratio 0.10`）；
4. **消息传递只用训练边构成的图**，验证/测试边只用于最后打分，绝不参与消息传递。

第 2 步是关键：若不去重，同一条边会以 `(u,v)` 与 `(v,u)` 两种形式分别进入训练集和测试集，
等于把答案抄给模型，AUC 会虚高到 0.99。第 4 步同样关键：若测试边参与消息传递，
节点 embedding 中就会混入测试边信息，评估不再公平。

### 2.3 负采样

- 训练阶段：每条正边配 `--neg_ratio` 条负边，默认 **1:1**；抽到自环或真实存在的边（假负样本）就丢弃重抽。
- 评估阶段：每条真边配 **100 条**负边，比训练严格得多。

### 2.4 模型：编码器—解码器

编码器与任务一完全相同（GCN / GAT(8 头) / GraphSAGE(mean) / GIN），
但最后一层**不做 softmax**，输出 `emb_dim` 维表示；解码器用内积（`dot`，参数为零）：

```
score(i, j) = z_i · z_j
```

本任务台账中所有 24 条记录的 `decoder` 均为 `dot`，未使用 MLP 解码器。

### 2.5 超参数（均来自 results.jsonl 记录字段与代码默认值）

| 参数 | 取值 |
|---|---|
| `emb_dim` | 64（节点 embedding 维度） |
| `hidden` | 128 |
| `dropout` | 0.5 |
| `layers` | 2 |
| `lr` | 0.01 |
| `epochs` | 100 |
| `decoder` | dot |
| `neg_ratio` | 1（训练时；来自代码默认值） |
| `val_ratio / test_ratio` | 0.05 / 0.10（来自代码默认值） |
| 采样模式 `batch_size` | Cora/Citeseer 256；Flickr 4096 |
| `num_neighbors` | [10, 10] |
| `seed` | 42 |

**评估频率**：Cora / Citeseer 每轮评估（图小、评估快）；Flickr 每 5 轮评估一次
（测试集有 450 万条负样本，评估很贵），但第 1 轮与最后一轮一定评估。

### 2.6 训练 / 验证 / 测试流程

同样**没有单独的 `test.py`**。`train.py` 一条龙完成：

```
读数据 → 无泄漏划分边 → 建「只用训练边」的图
→ 每轮训练，周期性在验证集上算 AUC
→ 记录验证 AUC，变好就存模型快照
→ 用验证集最优轮次在测试集上评估（AUC + Hits@50）
→ 追加写入 results/results.jsonl
```

### 2.7 评价指标

| 指标 | 含义 | 随机基线 |
|---|---|---|
| **AUC** | 随机取一条真边与一条假边，模型给真边打分更高的概率 | 0.5 |
| **Hits@50** | 每条真边与 100 条假边混合排名，真边排进前 50 名的比例 | ≈ 50/101 ≈ **0.495** |

AUC 用 Mann-Whitney U 统计量直接计算（不画 ROC 曲线、不依赖 sklearn），看整体排序质量；
Hits@50 看头部质量，更贴近推荐系统的业务需求。
**注意 Hits@50 的随机基线约为 0.5 而不是 0**，因此 0.6 并不意味着「学得不错」，
需要明显高于 0.5 才有意义（这一点与任务四从「全部实体」中排名的 Hits@10 完全不同）。

## 4. 结果分析

以下所有倍数/百分点均由第 3 节表格中的原始数值直接计算得到。

### 4.1 模型对比（性能）

- **GCN 在三个数据集上都是最优编码器**：Cora full 0.9398、Citeseer full 0.9212、
  Flickr sample 0.8349。这与「内积解码器 + 同配图」的经典结论一致，
  也说明在链路预测这一任务上，加权平均式聚合已足够。
- **Cora 上四模型排序清晰**：GCN 0.9398 > GAT 0.9120 > GraphSAGE 0.9046 > GIN 0.6137（全图）；
  采样模式下 GIN 从 0.6137 升到 0.7484（+13.47 pt），但依然垫底。
- **Cora 与 Citeseer 的差距很小且方向不一致**：GCN 全图 Cora 0.9398 > Citeseer 0.9212，
  而 GCN 采样 Citeseer 0.9137 > Cora 0.9054。链路预测主要依赖图结构而非节点特征质量，
  因此两个数据集上不出现节点分类那样的稳定差距。
- **Flickr 上出现明显的模型分化**：GCN 全图 0.7953 远高于 GAT 0.5885 与
  GraphSAGE 0.6562。GAT 在 Flickr 全图上的验证最优就是第 100 轮（0.5863），
  说明它在 100 轮内基本没有收敛到有意义的表示。
- **GIN 在 Flickr 上是明确的失败案例**：full test_AUC 0.0014、sample 0.0027，
  Hits@50 分别为 0.0014 和 0.0003 —— **远低于 0.5 的随机基线**，
  意味着模型系统性地给真边打了比假边更低的分数（排序反了）。
  这与 GIN 的求和聚合使数值随度数增长、在 Flickr 这种高度数图上不稳定有关。
  该结果应当作为负面结果如实保留，而不是当作「随机水平」忽略。

### 4.2 全图 vs 子图采样：性能

| 数据集 | 模型 | full test_AUC | sample test_AUC | 变化 |
|---|---|---|---|---|
| Cora | GCN | 0.9398 | 0.9054 | **−3.44 pt** |
| Cora | GAT | 0.9120 | 0.8994 | −1.26 pt |
| Cora | GraphSAGE | 0.9046 | 0.8560 | **−4.86 pt** |
| Cora | GIN | 0.6137 | 0.7484 | **+13.47 pt** |
| Citeseer | GCN | 0.9212 | 0.9137 | −0.75 pt |
| Citeseer | GAT | 0.8941 | 0.8881 | −0.60 pt |
| Citeseer | GraphSAGE | 0.8833 | 0.8588 | −2.45 pt |
| Citeseer | GIN | 0.7393 | 0.7678 | +2.85 pt |
| Flickr | GCN | 0.7953 | 0.8349 | **+3.96 pt** |
| Flickr | GAT | 0.5885 | 0.6581 | **+6.96 pt** |
| Flickr | GraphSAGE | 0.6562 | 0.6406 | −1.56 pt |
| Flickr | GIN | 0.0014 | 0.0027 | +0.13 pt（两者均失效） |

- **与任务一（Cora 采样全面更好）不同，本任务 Cora 上采样普遍更差**（−3.44 / −1.26 / −4.86 pt）。
  原因在于链路预测的采样定义不同：只有「两端都在种子集合里」的边才会被训练，
  因此采样模式实际看到的正边数远少于全图模式，梯度信号更稀疏；
  多走 10 倍步数不足以补回这部分信息损失。
- **Flickr 上却相反，采样对 GCN / GAT 明显更好**（+3.96 / +6.96 pt）。
  这与任务一的解释一致：每轮 22 次更新（全图仅 1 次）在单轮预算下走得更充分，
  而全图 Flickr 的 GAT / GraphSAGE 在 100 轮内尚未收敛（最优轮次均为第 100 轮）。
- **GIN 是全组唯一「采样救回来一些」的模型**，但 Cora 上 0.7484 仍低于其它三个模型的全图结果，
  Flickr 上更是完全失效，属于负面结果。

**总训练时间对比：**

| 数据集 | 模型 | 全图总训练秒 | 采样总训练秒 | 倍数 |
|---|---|---|---|---|
| Cora | GCN | 1.302 | 19.434 | 14.9× |
| Cora | GraphSAGE | 0.970 | 21.338 | 22.0× |
| Citeseer | GCN | 1.273 | 27.361 | 21.5× |
| Flickr | GCN | 71.952 | 309.469 | 4.3× |
| Flickr | GAT | 3.319 | 433.389 | **130.6×** |
| Flickr | GraphSAGE | 3.578 | 485.415 | **135.7×** |
| Flickr | GIN | 3.149 | 311.520 | 98.9× |

**结论：与任务一相同，采样训练在本实验规模下并不省时间，Flickr 上每轮慢 103~143 倍。**

原因同样是瓶颈错位：全图模式的瓶颈是 GPU 计算，而本任务模型很小（2 层、64 维 embedding），
Flickr 全图一次前向只要 0.03 秒量级；采样模式的瓶颈是 PyG 在 **CPU** 上做邻居采样与子图组装，
Flickr 每批 4096 个种子节点、两跳采样后子图很大，单步就要 0.14~0.22 秒，
且每轮有 22 步，GPU 大部分时间在等待 CPU。

**一处需要标注的异常值**：Flickr + GCN + full 的每轮耗时是 **0.5593 s**，而同一数据集上
GAT / GraphSAGE / GIN 的全图每轮分别只有 0.0307 / 0.0338 / 0.0301 s —— 相差约 18 倍。
在 Cora 与 Citeseer 上 GCN 全图反而是最快的（0.0106 / 0.0109 s）。
GCN 的参数量最小、结构最简单，没有理由在 Flickr 上比 GAT 慢 18 倍。
因此该数值极可能是运行时**显卡被其它进程占用**导致的（项目 README 记录过类似现象：
显存不足退化到共享内存后，每轮耗时可以从 3.24 秒膨胀到 728 秒）。
本报告如实保留原始数值，但提醒：Flickr + GCN 的「每轮 5.5 倍」这一倍率不适合作为
「GCN 对采样最友好」的证据。

**关于 Hits@50**：由于随机基线约为 0.495，表中有意义的读法是「明显高于 0.5」。
Cora/Citeseer 上多数模型在 0.90~0.98，属于有效学习；Flickr 上 GCN sample 0.9002 与
GCN full 0.8456 尚可；GIN 的 0.0014 / 0.0003 是排序完全反向的失效表现。

## 5. 踩坑与经验

以下条目均出自项目/任务 README 中**已经记录并已在代码里处理**的结论。

1. **链路预测的信息泄漏（本任务最重要的一条）**：划分边时若不去重（只保留 `u < v`），
   同一条边会以 `(u,v)` 和 `(v,u)` 两种形式分别进入训练集与测试集，AUC 会虚高到 0.99
   而模型实际上什么都没学到；同时**测试边绝对不能参与消息传递**，否则节点 embedding 里
   会混进测试边信息。本任务 24 条记录的 AUC 都落在合理区间（除 GIN 失效外），
   说明无泄漏划分生效。
2. **评估必须分块计算**：Flickr 的测试集有 450 万条负样本，一次性计算需要约 1 GB 显存
   直接爆掉，代码用 `score_edges_chunked` 按 30 万条一块分块打分，显存恒定。
3. **Hits@50 的随机基线约为 0.5 而非 0**：这是本任务特有的陷阱；看到 0.6 并不代表学得好。
   与之对比，任务四从全部实体中排名的 Hits@10 随机基线接近 0。
4. **负采样训练时不要开标签平滑**：标签从 `1/0` 改成 `0.9/0.1` 会给 BCE 损失引入
   约 0.325 的硬下界，模型学到这点区分度后损失就再也降不下去（实测卡在 0.3526）。
   任务四把标签平滑拆成两个参数处理；本任务默认不启用。
5. **PyG 版本锁 2.0.4**，GAT 多头拼接后的输出维度需用 `_conv_out_dim()` 正确计算，
   否则后续 BatchNorm 报维度不匹配。
6. **分析全图 vs 采样必须同时看 `steps_per_epoch`**：本任务两种模式的更新次数最多相差 22 倍
   （Flickr），只比「每轮耗时」会得出片面结论。
7. **GPU 被占用会让耗时失真**：项目 README 记录过并发运行导致每轮从 3.24 秒膨胀到 728 秒
   的实测教训，并因此规定「一次只跑一个任务」。本任务 Flickr + GCN 全图的 0.5593 s/轮
   很可能属于此类污染（见 4.3 节）。
8. **操作教训**：`run_all.py` 只看实验列表必须加 `--dry_run`；中断用 `Ctrl+C` 而不是
   `pkill -f run_all.py`；`--skip_done` 支持按配置断点续跑。

## 6. 结论

1. **GCN 是三个数据集上的最优编码器**：Cora full **0.9398**、Citeseer full **0.9212**、
   Flickr sample **0.8349**（对应 Hits@50 分别为 0.9753 / 0.9538 / 0.9002）。
   全台账最高 test_AUC 为 **0.9398**。
2. **GIN 在链路预测上表现最差，并在 Flickr 上明确失效**：full test_AUC 0.0014、
   Hits@50 0.0014，远低于 0.5 的随机基线，属于排序反向的负面结果；
   这也是本任务最值得记录的失败案例。
3. **全图 vs 采样的性能结论依赖数据集**：Cora 上采样普遍更差（−1.26~−4.86 pt，
   只有 GIN 例外 +13.47 pt）；Flickr 上采样对 GCN / GAT 更好（+3.96 / +6.96 pt），
   GraphSAGE 略差（−1.56 pt）；Citeseer 上差异较小（−2.45~+2.85 pt）。
   与任务一不同，本任务 Cora 上采样没有「多走步」的优势，反而因正边信号稀疏而下降。
4. **时间上采样不占优**：Flickr 上采样每轮比全图慢 **103~143 倍**，总训练时间最多慢 **135.7 倍**；
   瓶颈是 CPU 端子图组装。采样训练的价值在显存与可扩展性，而非速度。
5. **完成度**：24/38 个设计实验完成（主实验 24 个全部完成）；
   **学习率消融与层数消融（共 14 个）完全未运行**，因此报告要求 3.1 中「学习率、网络层数
   对性能的影响」在本任务缺少实测证据，这是最大的数据缺口，需要补跑。

## 7. 复现命令

在 `任务二_链路预测/code` 目录下执行（以下命令抄自任务 README，未改动参数）：

```bash
# 单次实验（训练 + 验证挑轮次 + 测试一条龙）
python code/train.py --dataset Cora --model GCN --mode full

# 采样训练（Flickr 需指定 batch_size）
python code/train.py --dataset Flickr --model GAT --mode sample --batch_size 4096

# 批量跑全部对比实验，100 轮
python code/run_all.py --stage all --epochs 100

# 只查看会跑哪些实验（务必加 --dry_run）
python code/run_all.py --stage main --dry_run

# 生成图表与汇总表
python code/plot_results.py

# 检查数据集是否就绪
python code/prepare_data.py
```

单次实验的完整参数（默认值，抄自任务 README）：

```bash
python code/train.py \
    --dataset Cora --model GCN --mode full \
    --decoder dot --emb_dim 64 \
    --batch_size 2048 --num_neighbors 10 \
    --neg_ratio 1 --val_ratio 0.05 --test_ratio 0.10 \
    --layers 2 --hidden 128 --lr 0.01 --epochs 100
```
